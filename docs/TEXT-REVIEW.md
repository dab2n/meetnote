# 관계 맵 문장 첨삭 의뢰

회의 전사문을 IBIS 구조로 정리한 맵의 **문장만** 고쳐 주세요. 구조(노드 종류·부모·개수·시각)는 그대로 둡니다.

## 지금 문제

기계 검사(`python3 ibis.py --audit`)는 **0건 통과**합니다. 글자 수도, 종결 형태도, 근거 구절도 규칙대로예요.
그런데 **사람이 읽으면 무슨 말인지 잘 안 들어옵니다.** 고쳐야 할 건 검사가 못 잡는 쪽입니다.

**① 쟁점 제목이 뭉뚱그려져 있다** — 무엇을 정해야 했는지가 안 드러남

| 지금 | 무엇이 문제인가 |
|---|---|
| `운동 전·중·후 제품 기능 범위` | '범위'를 정하려던 건지 기능을 고르려던 건지 모름 |
| `종목별 시나리오 구성 점검` | '점검'으로 닫아서 무엇을 봤는지 안 보임 |
| `무릎·발목 타깃의 근거` · `무릎·발목 설계 논리의 근거 점검` | 거의 같은 말이 두 논의에 따로 있음 |
| `제품 무드와 프로젝터 배치 방향` | 한 줄에 두 가지 |
| `로고와 네이밍의 개념 축` | '개념 축'은 회의에서 안 쓴 말 |
| `브랜드 컬러와 지면 투사 색` | 무엇을 정해야 하는지 없음 |

**② 결론 문장이 틀에 박혀 있다** — 같은 꼴이 반복돼 내용이 안 남음

```
방향은 유지하되 촬영 기반 실험을 덧붙이는 것을 조건으로 한다
논리는 받아들이되 객관적 출처 자료를 보충하는 것을 조건으로 한다
시나리오 구성은 받아들이되 Load 배치와 기술 근거는 재검토한다
```
`~하되 ~것을 조건으로 한다`가 조건부 결론마다 복붙처럼 반복됩니다. 번역투이기도 하고요.
`Load` 처럼 카드만 봐서는 모르는 말도 그대로 들어가 있습니다.

**③ 미결 제목이 너무 짧아 모호하다** — `과정 전시 방식`, `신발과의 결착 방식`

## 고치는 기준

`docs/SPEC.md`가 표준입니다. 전문을 읽고 작업해 주세요. 핵심만 옮기면:

**쟁점(`issue`)** — 그 자리가 어떤 자리였는지에 따라 꼴이 다릅니다.

| 그 논의가 | 이렇게 | 예 |
|---|---|---|
| 두 갈래에서 **고른** 자리 | 물음 `~인가` · `~할 것인가` | `부스트를 쓰는 단체 장면을 남길 것인가` |
| 값·대상·범위를 **좁혀 정한** 자리 | 명사형 안건 이름 | `프로젝터 장착 위치와 사출 범위` |
| 해 온 것을 **공유·점검**한 자리 | 명사형 안건 이름 | `인터뷰로 다시 잡은 제품의 중심 가치` |

고른 자리가 아닌데 물음으로 쓰면 없던 대립이 있었던 것처럼 읽힙니다. 8~30자.

**주장(`position`)** — 제안형으로 끝냅니다. `~하자` · `~해야 한다` · `~가는 게 맞다`. 12~60자.
**결론(`resolution`)** — `~하기로 한다`, 미결이면 명사형 안건 이름(6~30자, `여부`·`방향`·`범위`·`방식`으로 닫음).
**맥락(`note`)** — 제목만으로 빠진 것을 한 문장(25~70자). 제목을 바꿔 말하기만 한 문장은 금지.
**근거 구절(`ev`)** — **글자 하나도 바꾸지 마세요.** 전사문에 있는 그대로여야 합니다.

**문장 전체에 걸리는 규칙**
- 한국인이 **소리 내어 읽었을 때 걸리지 않아야** 합니다. 뜻이 맞아도 말이 안 되면 고칩니다.
- 금지: 뜻 없는 명사 덩어리(`강화 장면을 남길 값이 있다`), 번역투(`~하는 것을 조건으로 한다`), 조사 오용, 주어 없는 서술, **회의에서 쓰지 않은 한자어·외래어**.
- 전사문에 **없는 내용은 만들지 않습니다.** 뭉개진 대목은 비워 두는 쪽이 낫습니다.
- 같은 꼴을 여러 논의에 복붙하지 않습니다. 조건부 결론도 그 논의에서 실제로 걸린 조건을 그 자리의 말로 씁니다.

## 작업할 파일

```
docs/data/2026-06-15.ibis.json          ← 맵 (고칠 대상)
docs/data/2026-06-15.transcript.json    ← 원문 (근거)
docs/data/새로운 노트 (3).ibis.json
docs/data/새로운 노트 (3).transcript.json
```

고치는 칸: `sections[].title`, `nodes[].title`, `nodes[].note`, `resolution.title`, `resolution.note`,
`brief.line`, `brief.focus[].text`, `brief.story[]`, `sections[].flow[].text`, `todos[].text`

**건드리지 말 것**: `id` · `kind` · `parent` · `who` · `t` · `at` · `ev` · `from` · `conflicts` · 노드 개수와 순서

## 확인

고친 뒤 반드시 통과시켜 주세요.

```sh
python3 ibis.py --audit "docs/data/2026-06-15.ibis.json"
python3 -m json.tool "docs/data/2026-06-15.ibis.json" > /dev/null
```

검사는 **글자 수·종결 형태·근거 구절이 원문에 있는지**를 봅니다. 통과는 최소 조건이고,
위 ①②③이 실제로 읽히게 바뀌었는지는 사람이 봅니다. 한 논의씩 "이 카드만 보고 무슨 일이 있었는지 알겠는가"로 자문해 주세요.

# 함께 부탁드릴 것 — 카드에 사람 여럿 적기

같은 말을 여러 사람이 함께 밀었는데 지금은 **프로필이 한 명만** 뜹니다.

**스키마** — 노드에 `with` 칸을 이미 열어 뒀습니다 (`ibis.py` SCHEMA, `docs/SPEC.md`).

```json
{ "who": "일여", "with": ["하린"], ... }
```

- `who` = 그 말을 **처음 꺼낸 사람** 하나. 근거 구절 `ev`도 이 사람의 발언에서 찾습니다. **바꾸지 마세요.**
- `with` = 같은 말을 거들거나 그 자리에서 **같이 정한 사람**. 전사문에서 확인되는 사람만. 없으면 `[]`.

**화면은 이미 됩니다** — `docs/map.html` 이 `who` + `with` 를 프로필 겹쳐 놓기 + 이름(`일여 · 하린`, 셋 이상이면 `일여 · 하린 외 1명`)으로 그립니다. JSON 에 `with` 만 채우면 바로 보입니다.

**판단 기준** — 추측해서 넣지 마세요.
- 넣는다 · 같은 주장을 말로 거들었거나(`저도 그게 맞다고 봐요`), 결론을 함께 확인한 사람
- 넣지 않는다 · 그 자리에 있기만 한 사람, 다른 얘기를 한 사람, 반대한 사람(반대는 따로 `con` 카드)
