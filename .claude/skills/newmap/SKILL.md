# 회의 정리 맵 만들기

전사문 하나를 받아 `docs/data/<id>.ibis.json` 을 만들고 뷰어 목록에 올린다.
**추론은 내가 하고, 기계 작업은 `ibis.py` 가 한다.** 순서를 지킨다.

## 0. 준비

```bash
python ibis.py --read <전사문> --range 0:00 0:00 --width 40 | tail -1   # 길이·발언 수 확인
```

`docs/SPEC.md` 를 먼저 읽는다. 이 문서가 규칙의 전부다.
표본이 필요하면 `docs/data/2026-06-15.ibis.json` 을 본다.

## 1. 원문 읽기 — 한 번에 읽지 않는다

15~25분씩 끊어 **전부** 읽는다. 건너뛰지 않는다.

```bash
python ibis.py --read <전사문> --range 0:00 20:00
python ibis.py --read <전사문> --range 20:00 40:00
```

읽으면서 메모할 것: 무엇이 쟁점이었나 · 누가 어떤 주장을 했나 · 무엇이 부딪혔나 ·
어떻게 닫혔나(합의·조건·유보) · 웃음이 터진 대목.

**흔한 함정 셋.**
- 잡담·일정 확인을 섹션으로 만들지 마라. 실제로 논의를 움직인 것만 남긴다.
- "해봐야지 / 감이 안 와" 로 넘어간 것은 결론이 아니라 `open` 이다.
- 같은 사람이 자기 안을 갈아탄 것은 대립이 아니다. 대립은 표준 4절의 세 조건을 다 만족할 때만.

## 2. 초안 쓰기

`<id>.draft.json` 에 `SPEC.md` 형식으로 쓴다. 시각은 원문에 찍힌 것에서 고른다
(정확하지 않아도 된다 — 3단계에서 실제 발언 시작점으로 스냅된다).

문구는 종류에 맞는 서술형 한 문장으로. 발언을 그대로 옮기지 않는다.
`note` 는 그렇게 말한 근거를 한 문장으로.

## 3. 마무리 — 기계에 맡긴다

```bash
python ibis.py <전사문> --draft <id>.draft.json --id <id> --date 2026.06.15
```

시각 스냅 · 참조 정리 · 번호 재부여 · 전사문 저장 · `index.json` 갱신 · 표준 검사를 한 번에 한다.
**위반이 뜨면 초안을 고쳐 다시 돌린다. 0건이 될 때까지.**
규칙 자체가 틀렸다고 판단되면 `docs/SPEC.md` 를 고치고, 그러면 두 표본을 다시 검사한다.

## 4. 확인하고 올린다

```bash
python ibis.py --audit docs/data/2026-06-15.ibis.json   # 표본도 여전히 통과하는지
python test_meetnote.py
git add -A && git commit && git push                     # GitHub Pages 로 배포
```

뷰어에서 열어 노드가 제대로 이어졌는지, 카드 문구가 읽히는지 눈으로 본다.

## 이어지는 회의라면

직전 회의 맵의 `carry` 를 먼저 읽는다. 그 쟁점이 이번에 어떻게 됐는지 찾아
해당 섹션에 반영하고, 이번 회의의 `carry` 를 다시 쓴다.
